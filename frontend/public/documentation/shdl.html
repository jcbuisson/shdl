SHDL : Simple Hardware Description Language

Introduction

SHDL est un langage permettant de décrire des circuits numériques de manière simple et modulaire. Ce n’est pas un langage de programmation : il décrit les différentes équipotentielles qui composent un circuit ainsi que leurs relations combinatoires ou séquentielles. Une fois correctement décrit en SHDL, un circuit peut être « mis sous tension » et exécuté par simulation ou par synthèse sur un véritable circuit FPGA.

Voici un exemple de description d’un module combinatoire réalisant une addition sur 1 bit :

module fulladder(a, b, cin : s, cout)
   x = /a*b + a*/b
   s = /x*cin + x*/cin
   cout = /x*a + x*cin
end module

Voici un exemple de compteur asynchrone. Il utilise l’affectation séquentielle := et des vecteurs [1:0].

module clock2(rst, h : s[1:0])
   s[0] := /s[0] on /h, reset when rst
   s[1] := /s[1] on /s[0], reset when rst
end module

Les modules peuvent être réutilisés et les vecteurs peuvent être découpés :

module clock4(rst, h : s[3:0])
   clock2(rst, h : s[1:0])
   clock2(rst, s[1] : s[3:2])
end module

Équipotentielles : scalaires et vecteurs

Un scalaire représente une seule équipotentielle numérique ; il est désigné par un identifiant <nom_signal>, par exemple cout.

Un vecteur représente un ensemble ordonné d’équipotentielles ; il est noté <nom_signal>[<début>:<fin>], par exemple a[3:0]. Les indices doivent être dans l’ordre décroissant. Les vecteurs peuvent être composés à l’aide de l’opérateur « & », par exemple :

c3 & c2 & data[3] & c1 & data[2:0]

Modules

Un module peut inclure des instances d’autres sous-modules. Les dépendances circulaires dans la hiérarchie des modules sont interdites, car une conception modulaire doit toujours pouvoir être mise à plat sous la forme d’un ensemble fini d’affectations combinatoires et séquentielles. Comme dans les langages de programmation récursifs et modulaires, la modularité est essentielle pour simplifier la construction et favoriser la réutilisation ; contrairement à ces langages, l’autoréférence et les dépendances circulaires sont interdites.

Définition d’un module

/* module avec 3 entrées a,b,c
   et une sortie s */
module xor3(a, b, c : s)
   s = a*/b*/c + /a*b*/c + /a*/b*c + a*b*c // équation combinatoire
end module
module zero4(a[3:0] : Z)
   Z = /a[3]*/a[2]*/a[1]*/a[0]
end module

Le signe « : » dans la liste des paramètres est facultatif ; le statut d’entrée ou de sortie d’un paramètre est déterminé automatiquement lors de l’analyse syntaxique et sémantique.

Instanciation d’un module

module xor6(a, b, c, d, e, f, s)
   xor3(a, b, c, s1) // instance n° 1 du module xor3
   xor3(d, e, f, s2) // instance n° 2 du module xor3
   s = s1*/s2 + /s1*s2 // s = xor(s1, s2)
end module
module adder4(a[3:0], b[3:0], cin : s[3:0], cout)
   adder2(a[1:0], b[1:0], cin : s[1:0], c2)
   adder2(a[3:2], b[3:2], c2 : s[3:2], cout)
end module

Affectations combinatoires

« = » indique une affectation combinatoire.

Affectations combinatoires scalaires

// somme de termes
x = y*z + u*v*w

Affectations combinatoires vectorielles

// ici, x[7] = y[7]*z[7] + u[7]*v[7]*w[7], x[6] = y[6]*z[6] + u[6]*v[6]*w[6], :.
x[7:0] = y[7:0]*z[7:0] + u[7:0]*v[7:0]*w[7:0]

// *** erreur d’arité ***
x[7:0] = y[7:0] + z[3:0]

// les termes « ET » peuvent contenir des scalaires :  x[7] = u * y[7] * v * z[7], x[6] = u * y[6] * v * z[6],:.
x[7:0] = u * y[7:0] * v * z[7:0]

// une expression combinatoire entre parenthèses est une équipotentielle anonyme
y = x * (y + z)

// des constantes binaires peuvent être utilisées, à condition qu’elles aient la bonne longueur
x[3:0] = "1010"
s = 1

// l’opérateur « & » permet de concaténer des portions de vecteurs et des scalaires
message[6:0] = c3 & c2 & data[3] & c1 & data[2:0]
s[3:0] = "10" & a[1:0]

Affectations séquentielles

« := » indique une affectation séquentielle ; elle crée un point mémoire.

// s[3:0] mémorise et prend la valeur de d[3:0] sur le front montant de clk ; il est synchrone sur clk
// rst est une remise à zéro asynchrone : s[3:0] est mis à "0000" dès que rst=1, indépendamment de clk
s[3:0] := d[3:0] on clk, reset when rst

// toute expression combinatoire est autorisée à droite de « := »
x := y * (z + t) on h, reset when rst

// le changement se produit sur le front descendant de clk, avec remise à zéro dès que et tant que go=0
s[3:0] := d[3:0] on /clk, reset when /go

// la clause « enabled » est facultative
// ici, s[3:0] ne change que sur le front montant de clk ET si en=1 à cet instant
s[3:0] := /t[3:0]*s[3:0] + t[3:0]*/s[3:0] on clk, reset when rst, enabled when en

// l’état initial du point mémoire peut être 1 :
q := d on h, set on init

Modules intégrés

Leur nom commence par le signe « $ ».

Multiplication non signée

$umul16x16(a[15..0], b[15..0] : smul[31..0])

Ce module intégré multiplie deux entiers non signés de 16 bits et fournit leur produit complet sur 32 bits. Le résultat est combinatoire, sans horloge.

ROM

Le module intégré suivant réalise une ROM de 2^p mots de n bits :

$rom(address[p:0] : dataOut[n:0])

dataOut[n:0] présente de manière asynchrone le contenu de la case ROM située à l’adresse address[p:0].

RAM

Le module intégré suivant réalise une RAM de 2^p mots de n bits :

$ram_aread_swrite(clock, write, address[p:0], dataIn[n:0] : dataOut[n:0])
  • dataOut[n:0] présente de manière asynchrone le contenu de la case RAM située à l’adresse address[p:0], quelle que soit la valeur de write ou de clock
  • l’écriture dans une case RAM s’effectue de manière synchrone, si write = 1, sur le front montant de clock. Le contenu de la case RAM située à l’adresse address[p:0] est alors remplacé par dataIn[n:0]

Initialisation des mémoires

Les adresses et les valeurs acceptent les chaînes binaires avec le préfixe 0b ou les chaînes hexadécimales avec le préfixe 0x.

Dans le simulateur, un champ « Contenu des mémoires (.json) » apparaît lorsque le circuit contient des blocs RAM ou ROM. La liste indique leur ordre et la taille des adresses et des données. Vous pouvez télécharger un exemple JSON adapté au circuit, puis charger votre fichier : les sorties sont recalculées immédiatement. Le chargement manuel quitte le test sélectionné. Les adresses absentes du fichier conservent leur contenu actuel.

Voici un exemple de fichier pour 2 instances de mémoire (RAM ou ROM), la première de 8 × 3 bits, la seconde de 16 × 8 bits. Toutes les cases mémoire, ou seulement une partie d’entre elles, peuvent être définies. 

[
   {
      "0b000": "0b110",
      "0b001": "0b100"
   },
   {
      "0b0000": "0b01010101",
      "0b1000": "0b11001100"
   }
]

Synthèse sur une carte FPGA

La synthèse transforme un module SHDL et ses sous-modules en un circuit implanté sur FPGA. L’outil en ligne de commande nécessite Node.js avec npm et une installation de Xilinx Vivado compatible avec le FPGA Artix-7 XC7A100T des cartes supportées. Pour programmer la carte, celle-ci doit être allumée, connectée par USB et accessible depuis Vivado.

Configuration

Dans un terminal, lancez :

npx shdl-synthesis config

La commande demande les trois paramètres suivants et les enregistre dans ~/.shdl_config.json :

  • URL de la plateforme SHDL : par exemple https://app.shdl.fr, ou l’URL de votre serveur local.
  • Nom de la carte : nexys4 ou nexys4-ddr.
  • Chemin de l’exécutable Vivado : le chemin de la commande vivado sur votre machine.

Relancez cette commande pour changer de carte, de serveur ou d’installation Vivado.

Vérification et synthèse

Enregistrez et synchronisez d’abord votre module et ses dépendances sur la plateforme. Les commandes suivantes demandent l’adresse e-mail et le mot de passe de votre compte SHDL ; elles chargent les documents de ce compte depuis le serveur configuré. Chaque nom de module doit correspondre à un seul document SHDL.

# Vérifier un module et afficher la hiérarchie de ses sous-modules
npx shdl-synthesis check mon_module

# Synthétiser le module et programmer la carte
npx shdl-synthesis synthesize mon_module

# Synthétiser avec un fichier d’initialisation des mémoires
npx shdl-synthesis synthesize mon_module --memfile memory.json

Remplacez mon_module par le nom de votre module principal. La synthèse génère les fichiers VHDL, les contraintes de broches XDC et un script Tcl dans /tmp, puis lance Vivado pour effectuer la synthèse, le placement, le routage et la génération du bitstream. Le script programme ensuite la carte connectée. Les fichiers portent un nom composé du nom du module et d’un identifiant unique ; le bitstream a l’extension .bit.

L’option -m est équivalente à --memfile. Le fichier JSON contient un tableau de contenus, un par instance de mémoire dans l’ordre utilisé par la synthèse. Pour cette commande, utilisez des chaînes binaires sans préfixe pour les adresses et les valeurs, par exemple [{"000": "110", "001": "100"}] pour une mémoire dont les adresses et les données ont trois bits.

Interface du module principal

Les paramètres du module principal doivent porter exactement les noms des signaux de la carte choisie. Vous pouvez utiliser une partie de ces signaux et des portions de vecteurs. Un paramètre inconnu de la carte provoque une erreur de synthèse. Les sous-modules peuvent conserver leurs propres noms de paramètres.

module copie_switches(sw[15:0] : ld[15:0])
   ld[15:0] = sw[15:0]
end module

Dans les tableaux, « Entrée » désigne un signal reçu par le FPGA, « Sortie » un signal piloté par le FPGA, et « Entrée ou sortie » une broche Pmod dont le sens dépend de son utilisation dans le module.
